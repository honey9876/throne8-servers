# REDIS OPTIMIZATION: PERMANENT RULES (apply to every task)
1. MongoDB is the source of truth. Redis is a cache/accelerator, except for ephemeral data (presence, typing, rate limits).
2. If Redis is down/slow/corrupt, fall back to MongoDB. For security-critical checks (JWT blacklist) choose fail-open vs fail-closed explicitly, document why, and make it an env flag.
3. Never share data across users unless it is truly public. Every private key contains userId (or viewerId). Never cache passwords, tokens, OTPs, Aadhaar data, or other users' email/phone.
4. Do not change any API response shape, status code, or error message.
5. No TODOs, placeholders, commented-out code, `any` casts to silence errors, or empty catch blocks. Minimal diffs; no unrelated refactors.
6. Every write path (controllers, services, Mongoose hooks incl. findOneAndUpdate/updateMany/bulkWrite, admin routes, cron jobs, scripts, socket handlers) must invalidate or update its cache. List them explicitly.
7. Every Redis key has a TTL (with ±10% jitter), a namespaced versioned name (`app:v1:<domain>:<id>`), bounded length, and sanitized input. Use SCAN, never KEYS.
8. Every cache domain has an env kill switch (`CACHE_<DOMAIN>_ENABLED`). All TTLs come from validated env config.
9. Every Redis call is wrapped with timeout + try/catch + logging + fallback. No PII/secrets in logs or key names (hash emails).
10. Must work with multiple Node instances (PM2/cluster/docker).
11. After each task: `tsc --noEmit`, lint, full tests, and build must pass with no new warnings. Then STOP and report; wait for my "continue".
12. If anything is ambiguous or risky, ask me instead of guessing.
